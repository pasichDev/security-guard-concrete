# Security Guard для Concrete CMS

[English](README.md) · **Українська**

Веб-фаєрвол і панель безпеки для **Concrete CMS 9.5** — один пакет Concrete. Перевіряє
кожен запит до того, як Concrete його обробить, блокує атаки й підбір паролів і показує,
що відбувається на сайті — і з власного журналу подій, і з логів доступу хостингу.

Зроблено під реальний shared-хостинг (cPanel, ліміти ресурсів CloudLinux, вимкнений
`exec()`): жодного запиту до бази на звичайному запиті, жодних зовнішніх сервісів, і пакет
ніколи не кладе сайт — будь-яка внутрішня помилка пропускає запит далі.

> **Ліцензія: код відкритий для перегляду, усі права захищені.** Встановлення чи
> використання — лише з письмового дозволу автора. Див. [LICENSE](LICENSE).

## Можливості

- 🛡️ **Фаєрвол (WAF)** — сигнатури SQL-ін'єкцій, XSS, обходу каталогів, виконання коду,
  PHP object injection, XXE, SSRF, веб-шеллів, чутливих файлів (`.env`, `.git`, бекапи
  конфігів), пробінгу WordPress, експлойт-адрес Joomla, сканерів уразливостей і AI-краулерів.
- 🧱 **Експлойти Concrete CMS** — анонімний доступ до службових маршрутів `/ccm/system/*`
  (клас уразливостей, до якого належать розкриття даних 2026 року через відсутню перевірку
  прав), старі маршрути `/tools/`, внутрішні файли ядра, маршрути встановлення й оновлення,
  визначення версії. Список маршрутів, якими легітимно користуються анонімні відвідувачі,
  взято з ядра 9.5.2.
- 🔐 **Захист входу** — рахує невдалі входи з кожної IP, після порогу банить із відповіддю
  429, надсилає лист адміністраторам, автоматично довіряє IP адміністратора після входу.
- 🍯 **Пастки (honeypot)**, виявлення **сплесків PHP-проб**, **ліміт частоти**,
  **поведінковий скоринг**, виявлення **сплесків трафіку (DDoS)**.
- 🤖 **Пошуковики в безпеці** — Googlebot, Bingbot, YandexBot, DuckDuckBot, Applebot і
  Baiduspider перевіряються зворотним і прямим DNS; підробки ловляться; підтвердженого
  пошукового бота не забанити випадковим кліком.
- ⏫ **Ескалація банів** — 1 год → 24 год → 7 днів → 30 днів для повторних порушників;
  ручні й безстрокові бани; білий список з IP, префіксами й CIDR (IPv4/IPv6).
- 📊 **Панель** — огляд із графіками, журнал подій із фільтрами й експортом CSV,
  заблоковані IP, білий список, влучання в пастки, поведінкові бали, аналітика трафіку з
  логів хостингу, перевірка безпеки сервера, налаштування і картка для стартової сторінки
  дашборду.
- 📈 **Аналітика логів хостингу** — читає `access-logs/` cPanel і місячні `.gz`-архіви
  (формат Apache combined), рахує по днях ідемпотентно (повторні запуски й ротація логів не
  дають подвійного рахунку), бачить навіть статику, яку nginx віддає без PHP.
- 🧰 **Блоки сервера теж видно** — відповіді 403, які сервер віддає ще до PHP (фаєрвол
  хостингу на зразок ModSecurity/Imunify і правила `.htaccess`), розпізнаються в логах доступу
  за фіксованою сторінкою блокування й показуються окремим джерелом.
- 🔄 **Оновлення діапазонів ботів** — `security-guard:update-ranges` оновлює офіційні списки
  IP Googlebot, Bingbot, Applebot і DuckDuckBot (сувора перевірка, запасні вбудовані списки).
- 🌗 Темна й світла теми дашборду, мобільна верстка.
- 🌍 Мови: англійська, українська, польська, німецька, французька, іспанська, італійська,
  нідерландська, португальська (Бразилія).

## Безпечність закладена в дизайн

- **Режим спостереження за замовчуванням.** Після встановлення нічого не блокується —
  атаки лише записуються. Перегляньте журнал подій, потім увімкніть блокування на сторінці
  «Огляд».
- **Fail-open.** Будь-який виняток усередині фаєрвола пишеться в лог, а запит іде далі.
- **Адміністраторів і редакторів не блокує.** Користувачі з доступом до дашборду й IP з
  білого списку обходять перевірки; редактори, що увійшли, обходять евристики вмісту на
  `/ccm` і `/dashboard` (лише поки вимкнена публічна реєстрація).
- **Аварійний обхід.** Задайте токен у налаштуваннях і відкрийте
  `https://ваш-сайт/?sg_pass=<токен>`, щоб зняти бан із власної IP.

Подробиці: [docs/security-model.md](docs/security-model.md).

## Вимоги

- Concrete CMS **9.5.2** або новіша 9.x
- PHP **8.2** (MySQL/MariaDB, як у Concrete)
- Необов'язково: APCu (швидші лічильники; інакше — файлові)

## Встановлення

**Одним кроком на сервері з cPanel/SSH** (забирає публічний репозиторій, підміняє файли
пакета, виконує встановлення або оновлення, чистить кеш, перевіряє головну сторінку й
повертає попередні файли, якщо щось пішло не так):

```bash
VERSION=v1.2.0
curl -fsSL "https://raw.githubusercontent.com/pasichDev/security-guard-concrete/${VERSION}/bin/server-update.sh" -o ~/sg-update.sh
bash ~/sg-update.sh "${VERSION}"                     # без аргументу — найновіший тег vX.Y.Z
EXPECTED_SHA=<sha коміту> bash ~/sg-update.sh v1.2.0  # відмовитися, якщо тег вказує на інший коміт
```

Змінні: `SITE_ROOT` (за замовчуванням `~/public_html`), `PHP`, `SITE_URL`, `EXPECTED_SHA`, `REQUIRE_SIGNED=1`.
Коди виходу: 0 — готово, 1 — помилка (файли повернуто, якщо їх уже підмінили), 2 — вже йде інший запуск,
3 — встановлено, але перевірка головної не пройшла (файли лишено — база вже оновлена). Перед оновленням
зробіть бекап бази — зміни схеми не відкочуються.

**Вручну:**

1. Скопіюйте пакет у `packages/security_guard` вашого Concrete (назва теки — саме
   `security_guard`). `tests/` і `docs/` у публічний веб-корінь не копіюйте.
2. Встановіть: **Dashboard → Extend Concrete → Add Functionality** або з командного рядка:

   ```bash
   php concrete/bin/concrete5 c5:package:install security_guard
   ```

3. Відкрийте **Dashboard → Security Guard**. Пакет стартує в режимі **спостереження**.
4. У **Налаштування → Логи хостингу** додайте свою IP у виключення *до* першого імпорту,
   щоб ваш власний трафік не спотворював статистику.
5. Додайте завдання cron (нижче).
6. Коли кілька днів у журналі не буде хибних спрацювань — увімкніть режим **блокування**.

## Cron (імпорт логів хостингу й очищення)

```cron
15 * * * *    php /шлях/до/сайту/concrete/bin/concrete5 security-guard:ingest        >/dev/null 2>&1
*/15 * * * *  php /шлях/до/сайту/concrete/bin/concrete5 security-guard:cleanup       >/dev/null 2>&1
30 4 * * 1    php /шлях/до/сайту/concrete/bin/concrete5 security-guard:update-ranges >/dev/null 2>&1
```

На cPanel із CloudLinux вказуйте повний шлях до PHP, напр. `/opt/alt/php82/usr/bin/php`.

## Командний рядок

| Команда | Що робить |
|---|---|
| `security-guard:ingest [--rebuild] [--days=N] [--time-budget=S] [--log-root=DIR] [--domain=D] [--exclude-ip=IP]` | Дочитує нові рядки логів доступу хостингу й перераховує торкнуті дні. Код виходу 0 — готово, 1 — помилки, 2 — зупинено лімітом часу (запустіть ще раз, щоб продовжити). |
| `security-guard:cleanup` | Видаляє старі події, прострочені бани, застарілі бали й файли лічильників. |
| `security-guard:stats [--from=РРРР-ММ-ДД] [--to=РРРР-ММ-ДД] [--report-compat] [--json]` | Друкує таблицю денної статистики. |
| `security-guard:update-ranges [--force] [--dry-run]` | Завантажує офіційні списки IP пошукових ботів і зберігає їх, якщо вони пройшли перевірку. |

Кожна команда доступна також під псевдонімом `c5:security-guard:*`.

## Джерела логів

За замовчуванням пакет шукає `<home>/access-logs/<домен>` і
`<home>/access-logs/<домен>-ssl_log` та місячні архіви в `<home>/logs/`, де `<home>`
визначається з каталогу сайту, а `<домен>` — з канонічної адреси. Якщо хостинг кладе логи
деінде — задайте **Налаштування → Логи хостингу** (`log_root`, `log_sources`).

## Як додати мову

Додайте локаль і правило множини в `SG_LOCALES` у `tests/ui/strings_lib.php`, виконайте
`php tests/ui/sync_po.php xx_XX` — з'явиться `languages/xx_XX/LC_MESSAGES/messages.po` з усіма
рядками; перекладіть і виконайте команду ще раз — вона перевірить плейсхолдери й зкомпілює `.mo`.

## Видалення

**Dashboard → Extend Concrete → Security Guard → Uninstall**. Пакет прибирає свої сторінки
дашборду, таблиці в базі, налаштування й файли стану.

## Чого пакет не робить

- Не змінює ваш `.htaccess`. PHP-файли ядра, які Apache виконує напряму (наприклад, у
  `concrete/vendor/`), до фаєрвола не доходять — закрийте їх у конфігурації вебсервера.
- Не звертається до зовнішніх сервісів; країна для IP — офлайн-оцінка.
- Сторінки з повного кешу сторінок Concrete віддає анонімам ще до запуску пакетів, тож ці
  запити фаєрвол не бачить.
